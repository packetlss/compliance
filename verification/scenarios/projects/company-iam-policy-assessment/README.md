# Company IAM policy assessment

This fixed-time synthetic scenario selects exactly `host/A` and `host/B` in one
operation. Each host receives the company IAM requirement baseline and a
separately materialized restricted realization. That explicitly experimental,
non-frozen Requirement/Realization path requires four local access checks plus
an IAM check whose independent inputs establish an assertion about
`service/company-iam` and the exact host's relationship to it. The assertion
subject is never relabeled as its beneficiary. The company requirement's
24-hour value reaches every required evidence dependency.

Canonical mutations cover local/service failures, a wrong service, absent and
negative relationships, beneficiary isolation, nonselected C stability,
operation result matching, changed comparison plans, aged historical support,
and unsafe-routing refusal. Focused tooling and Rego tests retain exhaustive
malformed-input, criterion-error, waiver-boundary, and timestamp permutations.
Identity checks are relational; generated artifacts and digest constants are
not committed.

The conclusion is bounded to the exact supplied A/B inputs and recorded instant.
`example-regulatory-framework:IAM-01` is company-policy traceability only. Pass
does not establish external conformity, certification, legal applicability,
inventory completeness, continuous effectiveness, or assertion authority.
